# e2e перед коммитом

Тесты лежат в `frontend/e2e/`, конфиг — `frontend/playwright.config.ts` (сам поднимает dev-сервер
с тестовыми `VITE_OIDC_*`, чужой не переиспользует).

## Порядок

1. **Определи состав коммита:** `git status --short` и `git diff --cached --name-only`.
   Если все изменённые файлы — `docs/**`, `*.md`, `.claude/**`, `.gitignore` или `scripts/memory_tasks.json`, e2e не нужен:
   скажи об этом одной строкой и переходи к коммиту.
2. **Проверь окружение:** `node --version`, `ls frontend/node_modules/@playwright`.
   Нет Node или зависимостей — скажи об этом и остановись, не обходи молча.
3. **Запусти тесты:**
   ```bash
   cd frontend && npx playwright test --reporter=line
   ```
   Таймаут команды — 300000 мс. Если тесты начнут обращаться к бэкенду, он должен работать
   с `CMDB_AUTH_DISABLED=true` (см. комментарий в конфиге); поднимай его до запуска и гаси после.
4. **Результат:**
   - **Зелёный** — продолжай коммит по правилам из AGENTS.md (ключ Jira в заголовке, без `Co-Authored-By`,
     комментарий в Jira после коммита).
   - **Красный** — коммит не делай. Покажи, какие тесты упали и почему (путь к trace:
     `frontend/test-results/`). Предложи исправить; после правок запусти тесты заново.
   - **Не запустились** (нет браузера, нет системных библиотек, порт 5173 занят) — это не «зелёный».
     Назови причину и спроси пользователя, что делать.

## Запрещено

- Помечать тесты `skip`/`fixme`, ослаблять проверки или править конфиг, чтобы прогон прошёл.
- Коммитить при красном прогоне «чтобы потом починить», если пользователь прямо не разрешил.
- Запускать тесты со `--update-snapshots` без просьбы пользователя.

Если пользователь явно сказал «без e2e» / «пропусти тесты» — коммить, но отметь в ответе,
что e2e не запускались.
