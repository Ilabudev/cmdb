# Закрытие задачи Jira

Аргумент: из запроса пользователя — ключ задачи (`CMDB-N`), необязательно `--dry-run`.
Ключ нормализуй: обрежь пробелы и приведи к верхнему регистру (`cmdb-9` → `CMDB-9`); флаг ищи
среди слов аргумента в любом месте и в любом количестве пробелов.
После нормализации ключ не похож на `CMDB-<число>` или его нет — спроси пользователя и остановись.
С `--dry-run` выполни шаги 1–3 и покажи резюме и план, ничего не записывая (ни в Jira, ни в git).

## Порядок

1. **Состояние задачи.** Один вызов инструмента Jira для чтения задачи с `fields="summary,status,description"` и
   `include="comments"` (одного `comment_limit` недостаточно: без `include` комментарии не приходят),
   `comment_limit=100`. Статус уже `Done` — скажи об этом и остановись.
2. **Проверь, что закрывать можно:**
   - `git status --short` — дерево чистое. Есть незакоммиченные правки — остановись и скажи какие.
   - Коммиты задачи: `git log --format='%h %s' --grep='^<KEY> '`. Нет ни одного — спроси пользователя,
     закрывать ли задачу без коммитов.
   - Все коммиты задачи опубликованы: `git log origin/main..HEAD --grep='^<KEY> '` и то же для
     `github/main` пусты. Есть неопубликованные — остановись и предложи сначала запушить
     (`git push` спрашивает подтверждение, сам его не обходи).
3. **Составь итоговое резюме** на русском по коммитам (`git log`, тела сообщений) и комментариям задачи:
   - **Цель** — из описания задачи;
   - **Что сделано** — по коммитам, с хешами;
   - **Проверки** — только те, что подтверждены комментариями или сообщениями коммитов
     (pytest, ruff, e2e). Не выдумывай результаты, которых в источниках нет;
   - **Ограничения и что учесть** — если они были названы в задаче; иначе раздел опусти.

   Покажи резюме пользователю. Без `--dry-run` дальше иди без повторного запроса: вызов `$task-close`
   уже является явным указанием закрыть задачу.
4. **Запиши в Jira:** добавь комментарий с заголовком `## Итоговое резюме` и текстом из шага 3.
5. **Переведи в Done:** получи доступные переходы. Есть `Done` — выполни его. Нет (например, из `To Do`) —
   сначала `In Progress`, затем снова получи переходы и выполни `Done`. `Resolved` не используй,
   если `Done` доступен. Если `Done` недоступен совсем — остановись и покажи доступные переходы.
6. **Синхронизируй журнал:** `python3 scripts/update_memory.py` (статус подтягивается из Jira).
   Файлы не изменились — коммит не нужен, переходи к шагу 8.
7. **Закоммить статус** по правилам AGENTS.md: только `docs/memory.md` и `scripts/memory_tasks.json`,
   заголовок `<KEY> chore: статус задачи <KEY> в журнале — Done`, без `Co-Authored-By`.
   e2e для такого коммита не нужны (в нём нет кода). После коммита добавь в задачу комментарий
   с хешем и полным текстом сообщения (правило AGENTS.md).
8. **Отчёт.** Одной-двумя строками: задача закрыта, хеш коммита статуса, что он не запушен.
   Предложи запушить на `origin` и `github`; сам `git push` не выполняй без ответа пользователя.

## Запрещено

- Закрывать задачу при незакоммиченных правках или неопубликованных коммитах задачи.
- Выдумывать результаты проверок и состав работ, которых нет в коммитах и комментариях.
- Менять статус других задач, править код или документы, кроме `docs/memory.md` и
  `scripts/memory_tasks.json`.
- Использовать `git commit --amend`, `git push --force` или обходить запросы на подтверждение.
